P434: 9. Responsive Design Patterns
P435: Breakpoints
P436: Mobile-First Patterns
P437: RP-001: Sticky right-rail becomes bottom sheet
P438: Desktop right-rail lead form transforms to a bottom-sheet trigger button on mobile. Tap opens full-screen modal with the form.
P439: RP-002: Multi-column grids collapse gracefully
P440: 6-col desktop → 3-col tablet → 2-col mobile → 1-col small mobile. Never horizontal-scroll.
P441: RP-003: Tab navigation → dropdown on mobile
P442: 6-tab navigation on desktop becomes a dropdown selector on mobile to save vertical space.
P443: RP-004: Sidebar navigation → drawer on mobile
P444: Any sidebar navigation slides in from left (or bottom) as an overlay drawer on mobile.
P445: RP-005: Cards stack with generous spacing
P446: Card grids stack on mobile with 16px+ gap between cards. Touch targets 44px minimum.
P447: RP-006: Fixed-width tables become horizontal scroll or stacked
P448: Data tables either: (a) allow horizontal scroll on mobile with sticky first column, or (b) transform to stacked key-value pairs.
P449: RP-007: Images serve responsive srcset
P450: Different image sizes per breakpoint. Mobile users get mobile-sized images (2x for retina). Prevents bandwidth waste.
P451: Touch Interactions
P452: RP-008: Minimum touch target 44x44px
P453: Every tappable element (buttons, links, form controls) at least 44px x 44px per WCAG.
P454: RP-009: Hover states have touch equivalents
P455: Any hover interaction (tooltip, dropdown) also works on tap. Mobile users can't hover.
P456: RP-010: Swipe gestures for carousels
P457: Image galleries, featured university carousels swipeable horizontally. Also show pagination dots.
P458: RP-011: Pull-to-refresh disabled on data-heavy pages
P459: Buyer portal, dashboard pages disable browser pull-to-refresh to prevent accidental reloads.
P461: 10. Interaction Patterns
P462: Loading States
P463: Every async action shows a loading state within 300ms. Options:
P464: Skeleton loaders — for content pages (matches final layout structure)
P465: Spinner — for form submissions and quick actions
P466: Progress bar — for multi-step operations (form wizard, file upload)
P467: Placeholder text — for tables and lists ('Loading leads...')
P468: Form Interactions
P469: RP-012: Inline validation on blur
P470: Field validated when user tabs away. Error shown below field, red border. Successful validation shows green checkmark briefly.
P471: RP-013: Field errors clear on typing
P472: As soon as user starts typing in an errored field, error clears (optimistic). Re-validates on blur.
P473: RP-014: Submit button disabled until form valid
P474: Prevents wasted submissions. Button shows visual disabled state (grayed out). Tooltip on hover explains why disabled.
P475: RP-015: Loading state on submit
P476: Button text changes to 'Submitting...' with spinner. Button remains disabled to prevent double-submit.
P477: RP-016: Success confirmation clear and persistent
P478: Toast notification (top-right, 5s) OR inline success message. Never both. Refreshes only relevant data, not whole page.
P479: RP-017: Idempotency-Key generated per submission
P480: Client generates UUID Idempotency-Key when user first views form. Prevents accidental double-processing on network hiccup.
P481: Modal Patterns
P482: RP-018: Modals dismissible by clicking outside
P483: Except for modals requiring explicit action (confirmations, wizards).
P484: RP-019: Modals dismissible by Escape key
P485: Standard keyboard accessibility. Focus returned to triggering element on close.
P486: RP-020: Modal focus trap
P487: Tab key cycles only within modal. Prevents user from tabbing to page behind modal.
P488: RP-021: Backdrop dimmed
P489: Modal backdrop is 50% black overlay. Blurs (backdrop-filter: blur) on modern browsers.
P490: Feedback Patterns
P491: RP-022: Confirmation for destructive actions
